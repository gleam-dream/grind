# Oracle behavior ledger

Pinned oracle: Oban OSS `v2.24.1`, Git commit
`64b8481e5383f6bc46b7a5284e4ced3202dec9d5`, Apache-2.0. Harness command:
`nix develop --command ./scripts/test-postgres.sh`. The shell starts a fresh
local PostgreSQL cluster and separate Grind, schema-migration, storage-route,
Oban, and external-consumer databases; it removes the cluster on exit. Oban is
configured with `Oban.Engines.Basic`, `default: 1`, no plugins, and its own
migration. `OBAN-LICENSE.txt` preserves the oracle's Apache-2.0 notice. No
Oban Pro capability or Pro-equivalence is inferred or claimed anywhere in this
ledger.

## Last full run

- Root Gleam package (`gleam test` under `scripts/test-postgres.sh`): 228
  passed, 0 failures, against PostgreSQL 16.15. The current schema contract
  is v12 (see `docs/UNIQUENESS-CONTRACT.md` for the schema change and its
  user impact); there is no deployed-schema upgrade path from the prior
  experimental v10 marker. The disposable cluster's port is chosen at random
  per run and is intentionally not recorded here, since it carries no
  evidentiary weight and would otherwise go stale on the very next run. The
  cluster starts with `synchronous_standby_names=grind_never_standby` and
  `synchronous_commit=local`, so ordinary commits stay local; only tests
  that explicitly raise their own transaction's `synchronous_commit` back to
  `on` are affected. Per-increment count history is not kept here; each
  increment's own tests and mutation/red-green evidence are documented in
  `docs/RECOVERY-EVIDENCE.md` and `docs/UNIQUENESS-CONTRACT.md`.
- Oban oracle harness (`oracle/run.exs`, `mix run run.exs`): 6 observations
  emitted — success, terminal failure/discard, first retry, exhaustion,
  snooze, and the `Oban.Pruner` tick. Of those, success, first retry,
  snooze, and the pruner tick are "paired execution" rows: a Grind-side test
  runs against an equivalent isolated database in the same gate run and
  independently asserts its own normalized expectation for the same
  scenario (no runtime comparison of one system's output against the
  other's — see the category footer below); terminal failure/discard and
  exhaustion are read for orientation only, because Grind's terminal policy
  for exhausted/typed-failure jobs deliberately differs from Oban's (see the
  rows below).
- External consumer (`consumer`, `gleam test`): 11 passed, 0 failures. Its own
  increment history is likewise kept in `docs/RECOVERY-EVIDENCE.md` rather
  than nested here.
- This header is updated whenever a full gate run reproduces different
  counts. It replaces per-row port numbers and any ephemeral `/tmp` log path;
  neither is retained below because a disposable cluster's port and log path
  do not survive the run that produced them.

## Normalization

Omit generated job IDs and wall-clock timestamps; compare event outcome and
committed state; normalize Oban `completed` to Grind `succeeded`; preserve
queue, attempt count, and user value. Oban's success value is integer `42`;
Grind's typed JSON output is string `"42"`, an intentional codec-level
difference. Oban error metadata is not equivalent to Grind's caller-owned
typed error value.

An early standalone pure resolver experiment was removed when the response
resolver was consolidated into the same worker-definition path used by queue
execution. Its separate tests are not counted as production behavior
evidence. The public retry policy receives typed business failures only;
worker death, invalid input, and runtime faults do not enter that callback.

## Evidence categories

Every row carries exactly one of the following:

- **faithful port** — reproduces a named upstream test's contract (same
  trigger, same compared aspect, no deliberate difference in what is
  compared).
- **paired execution** — both Oban and Grind actually ran, in the same full
  gate run, against equivalent isolated initial conditions, and each side
  asserts its own normalized expectation for the same scenario. Nothing in
  the harness reads one system's result and compares it to the other's at
  runtime: the pairing is that both ran side by side in one gate, not that
  their outputs were diffed against each other.
- **inspired by upstream** — covers a related upstream behavior or reads an
  upstream source/test for orientation, without claiming an identical
  contract; used whenever the compared aspect's terminal state, accounting,
  or policy deliberately diverges, or the upstream side was not executed
  head-to-head with Grind.
- **original Grind contract** — exercises a requirement absent from the
  public Oban OSS oracle; no upstream contract is claimed for the compared
  aspect.
- **unverified** — a source or test was inspected, or a Grind-side test is
  planned, but no Grind-side local test has run yet. A source read or an
  unrun local test is never passing evidence.
