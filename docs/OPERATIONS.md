# Operating a Grind installation

Use the [README](../README.md) for compiled setup, typed admission and current migration calls. The [design](design/design-layer.pdf) defines authority and failure boundaries. Operator commands require application-owned permissions; attribution strings are not credentials.

Configure one schema per installation and PostgreSQL roles with the intended schema privileges. Grind preserves application search_path for shared-pool queries and scopes its own transactions. Client handle identity is a misuse check, not a cross-cluster authentication mechanism. Reusing a pool after Grind stop is invalid. Caller-owned transactions must be open READ COMMITTED SingleConnections in the same database; a staged enqueue reply does not prove COMMIT. A prior matching admission receipt does not prove a retry's business writes committed.

Apply current source migrations or their exact Cigogne mirrors using one agreed deployment procedure. Quiesce/drain consumers before locking upgrades, inspect current schema and physical shape, budget each step for real DDL/foreign-key validation, and rerun after uncertain reply to reread the lock-protected marker. Earlier committed steps remain. Unsupported experimental schema version 10 requires a deliberate reinstall/data strategy; no automatic deletion is performed. Do not rewrite released mirror SQL. Conformance and upgrade tests are the source of truth for versions 11–13.

For CommitUnknown retain the returned PendingSubmission and reconcile it; repeat a caller key only with its identical command. A missing receipt is still unknown, not proof of rollback. Stable ACK and resolution identities similarly reconcile the original disposition. Never repeat an external effect merely because its storage reply timed out. Receipt recovery ends when the job is pruned; use a separate business ledger for permanent deduplication.

List Uncertain jobs and investigate their external effects before ConfirmSuccess, ConfirmFailure or AuthorizeReplay. Encode confirmed values with the original contract. Pending cancellation blocks replay but allows terminal confirmation. Current cancellation-first ACK can turn explicit Uncertain into Cancelled and clear evidence; inspect application effect records as well as the uncertain listing. [ADR-0006](adr/0006-keep-cancellation-and-effect-uncertainty-distinct.md) records this unresolved gap. Cancellation and process termination cannot retract an effect.

Default local queue concurrency is ten, lease thirty seconds and polling 250ms. Account for one reserved renewal connection per used queue in addition to the main pool. Pending ACKs occupy local slots. L >= 4D validates an established progressing reserved connection; it does not guarantee liveness through reconnect, row contention or OS suspension. The pinned pool does not hard-bound queued checkout by D, and await within can be exceeded by its final read. Long pool waits need external operational monitoring and capacity planning.

Observe the sixteen typed Sinal descriptors in grind/telemetry: eight job lifecycle, two prune and six diagnostics. Use durable rows for outcomes; events can drop, duplicate and arrive out of order across producers. Monitor signed lease headroom, actual checkout wait, ACK retry phase and capacity including pending completion. Subscribers must never be required for correctness. Avoid job payloads and raw SQL/settings/exception terms in diagnostic metadata.

The pruner defaults to seven days, thirty-second intervals and batches of ten thousand. Only old finished terminal states are selected with SKIP LOCKED. Uncertain has no finished_at and is retained. Admission key locks can defer deletion of selected conflicts. Removing a job also removes all its receipts and reopens while_retained unique keys. FromSchedule periods can outlive a cancelled row's finished-time retention; the independent settings provide no cross-check.

Use cooperative stop and failed-start cleanup; direct raw application pog queries must drain under application ownership. Private driver topology and cache coupling require regression checks when dependencies change. Preserve finite runtime/pool naming; repeated consumer starts can allocate atoms that OTP does not reclaim. Connection poolers and encrypted fault coverage need explicit deployment qualification.

Historical measured findings live in ADR-0009 and qualify only their recorded source.
